# Монтаж кодом: montage-pipeline

Сырой дубль говорящей головы превращается в чистовик: без пауз, дублей и брошенных заходов.
Инструменты — из репозитория `github.com/qwwiwi/montage-pipeline` (MIT):

| Инструмент | Что делает |
|---|---|
| `roughcut.py` | первый заход: план реза по энергии звука, `--drop`, аудит, проверка речи, сборка, ускорение |
| `captions.py` | второй заход: субтитры ASS через libass поверх ЗАМОРОЖЕННОГО чистовика |
| `ffmpeg`, `ffprobe` | весь рез, склейка, прожиг, громкость, выдача |
| Groq `whisper-large-v3` | распознавание: границы предложений, проверка речи, текст субтитров |
| агент (ты) | выбирает, ЧТО выбросить: повторы, оговорки, брошенные заходы |
| HyperFrames (Apache-2.0) | второй заход сложнее субтитров: заголовки, плашки, призыв — HTML в видео |

Каждое число ниже измерено на четырёх реальных дублях с телефона (1080×1920, 30 к/с, HEVC,
80–133 с). Два правила реза, которые были опробованы и выброшены, оставлены нарочно — чтобы их
не выводили заново.

> **Журнал ошибок — [`docs/errors.md`](../../docs/errors.md).** Прочитай его перед началом работы.
> Нашёл новую проблему — сразу допиши запись (где · симптом · причина · исправление · правило ·
> статус), не откладывая на конец: база ошибок копится, чтобы следующий ролик собирался быстрее.

---

## Разделение ролей. Не обсуждается

**Агент решает, ЧТО резать. Код измеряет и исполняет. Внутри конвейера модели нет.**

| Кто | Что делает |
|---|---|
| код | измеряет исходник, находит паузы, исполняет план, доказывает, что речь не пострадала |
| агент | читает факты, решает, какие отрезки уходят, и объясняет почему |
| код снова | притягивает каждую названную агентом границу к измеренной тишине, отказывает там, где безопасно нельзя |

Модель нельзя исполнять вслепую, а код не имеет права на редакторское суждение. Обе половины
этого правила уже оплачены впустую потраченной работой — см. «Повторы».

## Подготовка

- `ffmpeg` и `ffprobe` в `PATH`, `curl`, Python только со стандартной библиотекой.
- ffmpeg должен быть собран с **libx264** (оба скрипта) и **libass** (`captions.py`). Проверь
  до начала: `ffmpeg -hide_banner -filters | grep -w subtitles`. Пусто — субтитры не прожгутся
  («No such filter»). Так бывает со сборкой ffmpeg из Homebrew по умолчанию.
- Репозиторий: `git clone https://github.com/qwwiwi/montage-pipeline` (если скилл ставили из
  него — второй раз не клонируй). Скрипты лежат в корне; в командах ниже вызывай их по полному
  пути `python3 <путь-к-репо>/roughcut.py`.
- Ключ распознавателя — ТОЛЬКО в переменной окружения `GROQ_API_KEY`. Не печатай его, не
  клади в аргументы команды, не пиши в файлы и логи. Скрипты сами передают его curl через
  стандартный вход.
- Без ключа `roughcut.py` работает, но режет только по звуку: теряет границы предложений и всю
  проверку речи. `captions.py` без ключа отказывает — текст субтитров не выдумывается.
- Один запуск — один файл. Склейки дублей и пакетной обработки нет.

## Рабочий порядок

Человек в петле на двух местах: список выбросов и швы. Не перепрыгивай их.

### 1. План реза

```bash
python3 roughcut.py дубль.mp4 --dry-run
```

Покажи человеку: порог тишины, сколько пауз найдено, сколько резов, сколько секунд уйдёт, итог
аудита. `--dry-run` проводит ТОЛЬКО аудит по энергии; проверка речи идёт лишь при настоящей
сборке с ключом. Форма вывода (дубль 79,73 с, только паузы, без `--drop`):

```
файл            дубль3.mp4, 79.73 с
порог тишины    -35.0 дБ (от речи, не от шума)
пауз найдено    40
резов           40, убрано 10.64 с
станет          69.09 с (сжатие 13.3%)
аудит тишины    чисто (громчайший сэмпл внутри вырезанного -35.0 дБ, -0.1 к порогу)
```

### 2. Разметка пауз и поиск повторов

```bash
python3 roughcut.py дубль.mp4 --silence mark
```

Печатает обычный отчёт (порог, резы, аудит), а за ним — окна вырезов тишины:
`начало - конец  пауза N мс (граница предложения)`. Время — секунды ИСХОДНИКА; окно — это уже
вырез с запасами по краям, а `пауза N мс` — длина измеренной паузы целиком. **Расшифровки в
выводе нет, повторы `roughcut.py` не ищет.** Это твоя работа, и делается она расшифровкой ПО
ФРАЗАМ (почему — см. «Повторы»). Нарезку на фразы делаешь ты сам, в коде её нет:

1. Фраза — речь между окнами, у которых `пауза ≥ 320 мс`. Окна с паузой короче склеиваются
   обратно внутрь фразы. Запас **150 мс** с каждой стороны, фраза короче **600 мс**
   присоединяется к соседней. Помни: окно уже ужато на 90/130 мс, так что у фразы по краям
   будет немного лишней тишины — это не вредит. Если `mark` запущен с `--drop`, выбросы тоже
   попадут в список как `пауза N мс` (N — длина выброса) — не принимай их за паузы.
2. Каждую фразу распознай ОТДЕЛЬНО. Ключ — через стандартный вход, как в скриптах:

```bash
ffmpeg -v error -y -ss "$A" -to "$B" -i дубль.mp4 -vn -ac 1 -ar 16000 -c:a pcm_s16le фраза.wav
printf 'header = "Authorization: Bearer %s"\n' "$GROQ_API_KEY" \
  | curl -sS --max-time 600 --config - https://api.groq.com/openai/v1/audio/transcriptions \
      -F model=whisper-large-v3 -F response_format=verbose_json \
      -F 'timestamp_granularities[]=word' -F file=@фраза.wav
```

`printf` — встроенная команда оболочки, ключ не попадает в список процессов. Никогда не добавляй
`-v` / `--trace` к curl и `set -x` в оболочку: они печатают заголовок с ключом. Таймкоды слов в
ответе — от начала ФРАЗЫ: прибавь `$A`, прежде чем сравнивать с исходником. Слова, чьё начало
дальше длины фразы, отбрасывай.

3. По каждой фразе собери факты: начало, конец, текст, `finished` (кончается точкой —
   многоточие НЕ считается), число слов-заполнителей, число слов, паузы до и после.
4. Предложи человеку список отрезков на выброс — с обоснованием по каждому: какая попытка
   фразы доведена до конца, какая полнее, держится ли соседний смысл.

**Не каждый повтор — рез.** В одном из дублей фраза сказана дважды намеренно, так написан
сценарий. Ты предлагаешь, человек подтверждает.

**Не придумывай таймкоды.** Всё, что предлагаешь резать, должно опираться на вывод инструмента
и распознавания, а не на пересказ.

### 3. Сборка чистовика

После подтверждения:

```bash
python3 roughcut.py дубль.mp4 --drop 29.6-31.4 --drop 60.8-62.8 --dry-run   # сначала план
python3 roughcut.py дубль.mp4 --drop 29.6-31.4 --drop 60.8-62.8 -o чистовик.mp4
```

- `--drop ОТ-ДО` — секунды ИСХОДНИКА, флаг можно повторять.
- Каждая граница притягивается к измеренной тишине. Граница уже внутри тишины — остаётся там,
  зажатая на 80 мс от краёв этого участка. Граница на речи — код берёт 3 ближайших участка
  тишины и выбирает первый, который лежит не дальше **500 мс** и длиннее 180 мс: начало выброса
  встаёт за 80 мс до конца этой тишины, конец выброса — через 80 мс после её начала (граница
  может уехать дальше 500 мс — предел считается до ближайшего края). Не нашлось — **отказ**
  (`ОТКАЗ: у границы 29.60 нет тишины в пределах 500 мс — резать там значит резать по слову`).
  Тогда предложи соседний интервал, а не другую цифру наугад. Граница внутри провала короче
  160 мс уйдёт за его край — и сборка откажет уже на аудите стыков. Надёжнее всего сразу
  ставить границы внутрь окон из разметки `mark` и **всегда сверять строку `снаплено` с тем,
  что ты задумал.**
- В отчёте появятся строки `решение модели … -> снаплено в тишину …` и `стыки модели`.
- **Ловушка отчёта:** выброс почти всегда перекрывает вырезы тишины, а `убрано`, `станет` и
  `расхождение с планом` считаются простой суммой вырезов — перекрытие считается дважды. Живой
  прогон: план обещал 51,96 с, собрано 58,97 с, «расхождение 7002 мс» — брака нет, двойной счёт
  8,8 с. Сам рез верный (склейка перекрытия сливает). Итог сверяй по факту: длительность файла ×
  ускорение = сумма оставленных отрезков.
- По умолчанию в конце ускорение **1,3**. Без него: `--speed 1.0`. Допустимо 0,5–2,0, иначе
  отказ.
- `расхождение с планом` — не гейт, `roughcut.py` на нём не падает. Читай это число сам: так
  ловится сломанный темп (см. `setpts` в ловушках).

### 4. Швы глазами

```bash
python3 roughcut.py дубль.mp4 --drop … --dry-run --seams ./швы
```

Кладёт в `./швы` картинки `seamNN.png`: кадр до и кадр после шва, рядом. Покажи их человеку —
джамп-каты машина не оценивает.

**Ловушка:** инструмент делает листы только для ПЕРВЫХ 8 швов по времени. Швы от `--drop`
дальше по файлу туда могут не попасть — а именно они важнее всего. Недостающие собери сам тем же
способом (кадр за 40 мс до начала выреза, кадр через 40 мс после конца, `hstack`).

Если на шве человек сменил позу — сдвинь границу `--drop` к соседней паузе. Режим
`--silence speed` сюда НЕ подходит: он глобальный (на весь файл, а не на один шов) и **не
вырезает `--drop`** — выброшенная речь проигрывается ускоренной ×6, и ни одна проверка этого не
ловит. `speed` — только для дублей без выбросов.

Листы для недостающих швов собирай по строке `снаплено в тишину`, а не по аргументам `--drop`.

### 5. Субтитры — только после «ок» на швы

```bash
python3 captions.py чистовик.mp4 --preset quiet --fontsdir ./fonts -o готово.mp4
```

Работает поверх готового чистовика и ничего не знает о резах. Текст — из повторной расшифровки
готового файла. Если длительность изменилась на **0,05 с** или больше — отказ.

### 6. Громкость и выдача — последним шагом

См. «Громкость» и «Выдача». Всё это делается над файлом, который уедет зрителю, и больше ни над
чем.

### Жёсткие правила процесса

- Порядок **рез → проверка → ускорение** обязателен. Не подставляй ускорение раньше.
- Упал аудит по энергии — не обходи его флагами. Покажи человеку, какой рез не прошёл.
- Проверяй гейты по коду выхода, а не по хвосту вывода: `| tail` прячет код возврата.

## Правило 1: рез разрешает энергия. Расшифровка — никогда

Замеры на четырёх дублях, Groq `whisper-large-v3-turbo`, русский:

- медианная длительность слова **280 мс**, а одному «слову» («Продолжение») распознаватель выдал
  **29,86 с**;
- на файле длиной **85,2 с** он вернул слова до **115,06 с** — выдумал «Продолжение следует…»
  на месте тишины в конце;
- интервалы слов регулярно заглатывают тишину вокруг, некоторые зазоры выходят отрицательными.

Это не особенность нашего звука, а открытые баги Whisper: `huggingface/transformers#36228`
(на 62-секундном файле слова до 87,22 с, открыт с февраля 2025) и `faster-whisper#125`
(выравнивание деградирует на длинной паузе и размазывает слово по ней).

```
Таймкод в расшифровке — это догадка модели.
Огибающая энергии — это измерение.
Резать можно только по измерению.
```

Расшифровка нужна, чтобы ПОНИМАТЬ (что сказано, где кончилась мысль), а не чтобы РАЗРЕШАТЬ или
запрещать рез.

**Жёсткое правило, закрытое тестом:** любое слово, чьё начало выходит за длительность файла,
отбрасывается ДО всякой обработки. Оба скрипта делают это с расшифровкой ИСХОДНОГО файла и
печатают `ОТБРОШЕНО N слов(а)`; повторное распознавание склеенного звука в `roughcut.py` так не
фильтруется. Если ты сам разбираешь ответ распознавателя — отбрасывай всегда. На живом прогоне
22.09 распознаватель снова выдумал 2 слова за концом 105,93-секундного файла.

### Два правила, которые опробовали и выбросили

1. «Рез должен стоять в 60 мс от границы слова по распознавателю». Выбросил **82 настоящих паузы
   из 144**.
2. «Вырезаемое не должно задевать надёжное ядро слова (интервал слова, ужатый на 80 мс с каждой
   стороны)». Ещё хуже — осталось **38** резов.

Обе ошибки одинаковы по природе: они доверяют догадке больше, чем измерению.

## Правило 2: порог тишины — от РЕЧИ, а не от шума

```
порог = clamp( p75(огибающей) − 6,5 дБ , −46 дБ , −30 дБ )
```

Огибающая: 16 кГц моно, окно 20 мс, шаг 10 мс, из сырых сэмплов.

Привязка к ШУМУ (10-й процентиль + 6 дБ) дала **−49 дБ** в тихой комнате и потеряла половину
пауз: комнатный тон громче такого порога. Привязка к речи даёт около **−34 дБ** на этом
материале и сама подстраивается под громкую или тихую запись.

Фиксированный порог (например, −35 дБ, как в OpenMontage) ломается в обе стороны: на тихой
записи режет речь, на громкой не находит пауз вовсе.

> **OpenMontage — AGPL-3.0.** Встроишь его код в сетевой сервис — обязан открыть исходники СВОЕГО
> сервиса. Идеи не лицензируются: режим ускорения пауз взят оттуда как идея и написан заново.
> Ни строчки их кода.

## Правило 3: край паузы не трогаем никогда

| Где | Остаётся запас |
|---|---|
| внутри фразы | 90 мс |
| на границе предложения | 130 мс |
| в самом начале клипа | 200 мс |
| в самом конце клипа | **600 мс** воздуха |

Паузой считается провал от **260 мс**. Вырезать меньше **60 мс** не стоит склейки. Точность
постановки реза, измеренная: **33–40 мс**.

Конец не симметричен началу: с запасом 200 мс ролик кончался ровно через 200 мс после последнего
слова и ощущался оборванным. Начало можно резать плотно, конец — нельзя.

## Что делать с паузой: три режима

| Режим | Что происходит | Когда брать |
|---|---|---|
| `--silence remove` | пауза удаляется — джамп-кат | речь ровная, поза не меняется |
| `--silence speed` | пауза остаётся, но пролетает (по умолчанию ×6, `--silence-speed`) | человек в паузе двигается: склейки нет, потому что её нет. **Только без `--drop`**: выбросы в этом режиме не вырезаются, а ускоряются |
| `--silence mark` | ничего не собирается, печатается список пауз | решение принимает агент или человек |

На одном и том же дубле: вырезание дало **−13,6%**, ускорение пауз **−10,5%**. Режим `speed`
экономит меньше и не показывает ничего.

## Четыре проверки, и они задают РАЗНЫЕ вопросы

### Первая и вторая: аудит по энергии, два вида реза

| Вид реза | Что должно выполняться |
|---|---|
| **рез тишины** | внутри вырезанного нет ничего слышимого. Это и есть всё утверждение |
| **рез модели** (`--drop`: повтор, неудачный заход) | внутри речь НАМЕРЕННО. Проверяются оба СТЫКА — они обязаны попадать в тишину |

Эта разница стоила ложной тревоги: первая версия проверяла нутро каждого выреза и провалилась на
трёх файлах из четырёх с превышением **+17…+21 дБ**. Дефекта не было — вопрос был не тот. После
разделения: аудит тишины чист на всех четырёх, стыки чисты с запасом **0,2–6,8 дБ** ниже порога,
**0 из 161** вырезанных участков содержал сэмпл, дотянувшийся до порога.

Аудит по энергии — главный гейт: только он доказывает, что речь не задета. Не прошёл — сборка
падает, а не выдаёт брак.

### Третья: распознать результат заново

После реза звук склеивается на ИСХОДНОЙ скорости и распознаётся ещё раз, слова сравниваются с тем,
что должно было остаться.

- Сравнивать надо со словами внутри оставленных отрезков, а не с полным исходником — иначе
  намеренно выброшенный дубль зачтётся как ущерб.
- У распознавателя своя изменчивость («5» → «пять», «код» → «год»), поэтому токены
  нормализуются, а порог — настройка. **Никогда не 100%.** На чистых сборках наблюдали
  **86–97%**. Порог `--min-similarity 0.80` нарочно мягкий: 0,85 дал бы ложный отказ на хорошем
  резе при первом капризе распознавателя. Ниже порога сборка всё равно откажет — но это второй,
  независимый сигнал, а не доказательство. Доказывает, что речь не задета, только аудит по
  энергии. Поднимать порог ради «строгости» нельзя.
- Бонус, оказавшийся важнее самой проверки: второй проход слышит то, что скрыл первый.

### Четвёртая: шов глазами

Машинные проверки отвечают только на вопрос «не срезали ли речь». О том, ВИДНО ли склейку, они не
знают ничего: человек в паузе меняет позу, а звук идеально чист. Поэтому `--seams` — единственная
проверка, которую делает человек, и ей подаётся подготовленный материал, а не «посмотрите
результат внимательно».

---

## Ускорение 1,3 — и почему оно последним

1,3 — это стиль, а не подтяжка: заметное ускорение, незаметный диапазон — 1,05–1,15. `atempo`
растягивает время, не сдвигая тон, голос не запищит.

**Порядок обязателен: рез → проверка → ускорение.** Если ускорить раньше, все измеренные
таймкоды разъедутся и аудит проверит не то, что вырезано. Вторая причина — измеренная. Один
файл, буквально один и тот же план реза:

| | Длительность | Проверка речи | «Потеряно» слов |
|---|---|---|---|
| проверка ПОСЛЕ ускорения | 53,00 с | 0,8478 | **3** |
| проверка ДО ускорения | 53,00 с | **0,8698** | **0** |

Эти три слова никто не резал: аудит тишины в обоих прогонах чист. Распознаватель просто хуже
слышит ускоренную речь. Побочная выгода: звуковая склейка стоит доли секунды, поэтому видео
кодируется один раз, а не два. Итог на этом файле: **79,73 с → 53,00 с, −33,5%**.

---

## Повторы: их ищет модель, и расшифровка должна быть ПО ФРАЗАМ

Эвристика поиска повторов (совпадение по корням, префиксное покрытие, проверка непрерывности
перечислений) нашла **0,4 секунды** на четырёх дублях. Человек, прочитавший те же расшифровки,
нашёл **47 секунд** за пару минут. Разрыв в сто раз. Выбор между двумя попытками одной фразы —
суждение о смысле, стеммер этого не может.

**Код отдаёт факты, решает модель.** Ни одной оценки «лучше — хуже» в коде.

### Цельная расшифровка не найдёт повтор ни при какой модели

Доказано на одном отрезке (второй дубль, 29,6–33,5 с):

| Что распознавали | Результат |
|---|---|
| весь файл, turbo | «Пятое. Совет для решения» **один** раз, вторая попытка спрятана внутри «слова» длиной 2,48 с |
| весь файл, полная `large-v3`, тишина вырезана заранее | всё равно **один** раз |
| два речевых отрезка по отдельности | «Пятая. Совет для решения...» и «Пятое. Советные решения.» |
| окно 5,9 с, содержащее оба | фраза **дважды**, дословно |

Декодер, только что выдавший предложение, видит его снова и считает зацикливанием. Никакая
модель этого не чинит. Расшифровка по фразам на тех же четырёх дублях нашла **8 повторов**
автоматически, включая все крупные. Цельный проход — **0**.

> **Фраза, а не «озвученный участок».** Нарезка по участкам выше порога дала мусор («кормлю»,
> «Которую можно сапогатить»): речь проваливается ниже порога между слогами. Фраза кончается на
> измеренной паузе от **320 мс**; всё короче склеивается обратно. Запас 150 мс, минимум 600 мс.

### Признак того, что расшифровка что-то скрывает

```
миллисекунд на символ  >  4 × медианы ЭТОГО файла     И     внутри есть звук выше порога
```

Медиана на этом материале **53–54 мс/символ**. На 6:45 речи признак подсветил ровно **4** места,
и каждое оказалось настоящей ошибкой распознавателя. Подтверждать найденное — распознаванием
ЭТОГО отрезка отдельно: на узком куске слову негде растянуться.

## Субтитры (`captions.py`)

| Пресет | Вид |
|---|---|
| `quiet` — **канон** | тонкая обводка 4 px, без заливки и плашки, 52 px |
| `plate` | строка на подложке, читается на любом фоне (задумана полупрозрачной — см. ниже) |
| `outline` | задуман как толстый контур без подложки, стиль ленты новостей (см. ниже) |

`--highlight &H004DD3FF` — подсветка звучащего слова. Строки собираются по трём причинам: длина
`--max-chars 32`, пауза `--max-gap 0.45` с, знак конца предложения.

**Что пресеты дают на самом деле — по коду, проверь одним кадром.** У `outline` цвет контура
`&HFF000000`, а альфа FF в ASS — полная прозрачность: контура не будет, выйдет жирный белый
текст. У `plate` стиль рамки 3, а libass заливает такую плашку цветом контура (`&H00000000`) —
она выйдет непрозрачной чёрной, а не полупрозрачной. До прожига целого ролика сделай
`--ass-only` и прожги один кадр (`-ss 5 -frames:v 1`), посмотри глазами.

**`--y` — это Y нижнего края строки от ВЕРХА кадра**, в пикселях этого кадра. Подсказка
`--help` («отступ снизу») говорит обратное — не верь ей, иначе передашь 520 вместо 1400. Для
кадра не 1920 по высоте пересчитай пропорционально.

**Ширину `captions.py` не меряет.** В разметке `WrapStyle: 2` — перенос выключен, длинная строка
просто обрежется краем кадра. Держит только `--max-chars`; для крупного `outline` (58 px, жирный)
уменьшай его и проверяй кадром.

**Пути.** `captions.py` собирает фильтр `subtitles=<путь>.ass:fontsdir=…` строкой: `:`, `,` или
`'` в пути ломают граф фильтров. Держи файлы в путях без этих символов. Рядом с выходом остаётся
файл `.ass`.

**Положение.** Канон — строка на `y = 1400` от верха кадра 1080×1920, НИЖЕ лица. Безопасная линия
Reels — **1248**: при крупной съёмке подпись на ней ложится поперёк рта, поэтому канон её
нарушает сознательно. Плата названа прямо: ниже 1248 Instagram может перекрыть подпись своим
интерфейсом. Нижние 300–400 px заняты интерфейсом всегда, промежуток 1248…~1500 обычно свободен,
но его высота зависит от ДЛИНЫ подписи к посту. **Правило: когда субтитры ниже безопасной линии,
текст под роликом держат коротким.**

**Шрифты.** libass ищет шрифт через fontconfig и, не найдя, молча подставит чужую гарнитуру —
ошибки не будет, будет чужой шрифт. Всегда передавай `--fontsdir` с файлом шрифта (Golos Text,
OFL, есть кириллица). Кириллицу проверяй рендером настоящего слова, а не названием семейства.

**Ширина.** Считай ширину текста тем же шрифтом и кеглем, каким рисуешь, и уменьшай кегль под
безопасную ширину. Русские слова длиннее английских — переполнение по умолчанию, а не исключение.
Центрирование двух слов каждого по своей ширине склеило их в `ЭТОДАШБОРД`: пару раскладывают от
центральной линии наружу. Два утверждения, которые надо проверять на каждой группе: ни одно
слово не шире полосы (слово не переносится — оно обрежется) и ни одна группа не длиннее двух
строк (третья уходит за низ кадра). На живом ролике: самая широкая группа **1111 px** против
полосы **872 px** — переносится в две строки; слов шире полосы 0, групп в три строки 0.

Размещать подпись по НАЙДЕННОМУ лицу пока не решено: нужен детектор с чистой лицензией. YOLO от
Ultralytics — AGPL, отброшен; кандидаты на проверку — каскады OpenCV (BSD) и MediaPipe
(Apache-2.0).

**Текст не придумывается.** Он берётся из расшифровки. Правка отдельного слова допустима, замена
фразы — нет: иначе видео начинает врать.

**Цена.** Связка «рез, затем субтитры» перекодирует видео дважды — это потеря поколения.
Осознанная плата за то, что второй заход не знает о резах.

## Два захода, и шов между ними заморожен

**Заход первый — чистовик** (`roughcut.py`): ровная речь, законченное видео, которое можно
смотреть как есть. Кадр не тронут, ни одной подписи.

**Заход второй — оформление** (`captions.py`, HyperFrames): заголовок, субтитры, плашки,
призыв — поверх готового чистовика.

> **Второй заход не имеет права двигать рез.** Ни длину, ни склейки, ни тайминг. Если подпись
> сдвинет склейку, все доказательства первого захода становятся доказательствами ДРУГОГО файла.
> Заморозка делает первый заход доказанным раз и навсегда, а оформление можно перебирать сколько
> угодно без перемонтажа.

Между заходами — **карточка стиля** из референсов владельца: какие подписи, какой ритм, где
наезды. Без неё оформление становится вкусом того, кто рендерит.

## Второй заход на HyperFrames

HyperFrames рендерит видео из HTML-страницы: тайминги объявлены атрибутами `data-*`, одна
остановленная временная шкала GSAP делает страницу перематываемой, воспроизведением медиа управляет
рендерер, а не страница. Лицензия Apache-2.0 — и это причина выбора: Remotion платный и прямо
запрещает принимать чужие композиции на рендер.

Первый заход (энергия, швы, речь) остаётся в ffmpeg и нашем коде. HyperFrames о паузах не знает.

> **Заморозка действует без исключений.** HyperFrames перекодирует всё видео через Chrome и МОЖЕТ
> молча изменить длину. Сравни длительность до и после: любое расхождение — отказ, а не
> округление.

Установка на голой машине:

```bash
npm i -g hyperframes
hyperframes browser ensure     # нужен unzip, без него падает без внятного сообщения
hyperframes doctor             # должен закончиться «Ready to render.»
hyperframes skills update      # контракт авторинга в виде скиллов — прочти до того, как писать HTML
```

Форма, которая рендерится:

- корень `<div data-composition-id data-width data-height data-duration>`, без обёртки
  `<template>` на верхнем уровне;
- `<video muted playsinline>` для картинки и ОТДЕЛЬНЫЙ `<audio id=…>` для звука, тот же файл.
  `<audio>` без `id` не попадает в микшер — **рендер выходит немым**;
- никогда не ставь `data-start` одновременно на `<video>` и его обёртку — линт отклоняет, и отказ
  по делу (не те кадры исходника, потом клип пропадает);
- ровно одна `gsap.timeline({paused:true})`, зарегистрированная в `window.__timelines["<id корня>"]`;
- каждому названному шрифту — `@font-face` на локальный файл, иначе headless молча подставит свой;
- вариативный шрифт по умолчанию отдаёт САМОЕ ТОНКОЕ начертание: объявляй `font-weight: 100 900`.

Композицию генерируй кодом из файла слов, а не пиши руками: на 67-секундном дубле одних субтитров
было 84 группы, каждая привязана к измеренному таймкоду. Рукописный HTML не переживёт перемонтажа.

**Гейт `hyperframes check` ловит настоящее:** наложение слов заголовка при переносе
(`line-height: 1.02`), наложение призыва на субтитры, перехлёст соседних субтитров на кадр от
округления `data-duration` до сотых, слабый контраст заголовка (белое на ярком, 1,36:1). Два из этих
случаев — продуктовые решения, а не CSS: в окне призыва субтитры ОСТАНАВЛИВАЮТСЯ (одно сообщение
на кадр), а между соседними субтитрами — зазор в два кадра и тайминги с тремя знаками.

> Ошибка линта выключает аудиты раскладки и контраста, и `check` сообщает `0 sample(s)` — выглядит
> как чистый файл, а значит «ничего не запускалось». Сначала убери ошибки.

**Чего гейт не видит:** он сэмплирует время и прошёл мимо субтитров, обрезанных с обеих сторон
кадра, — нашлось глазом на контактном листе, случайно, на 3 группах из 84. Ширину СЧИТАЙ тем же
шрифтом (см. «Ширина» в субтитрах), а после `check` сними контактный лист
`hyperframes snapshot --at <времена>` и посмотри на него.

**Потоки.** Один и тот же 67,2-секундный ролик, 2016 кадров, 4 vCPU:

| Потоки | По стене | к реальному времени | Съёмка кадров |
|---|---|---|---|
| `-w auto` → **1** | 5 мин 40 с | 5,06× | 5 мин 21 с |
| `-w 3` | **4 мин 18 с** | **3,84×** | 2 мин 42 с |

Передавай `-w` явно. Оба прогона дали ровно **67,200000 с** — заморозка выдержала смену числа
потоков. Съёмка в обоих откатилась в режим скриншотов вместо `beginframe` (подозрение —
программный GL на машине), так что 3,84× — ещё не оптимизированная цифра. Выход тяжёлый: при
качестве `-q looks` 131,6 МБ (125 МиБ) на 67 с — нужен отдельный шаг выдачи.

## Громкость — последним шагом, в выдаче

| | Интегральная | Диапазон |
|---|---|---|
| сырой дубль | **−26,1 LUFS** | 4,0 LU |
| чистовик до этого шага | **−25,8 LUFS** | 3,0 LU |
| опубликованные рилсы того же автора (монтировал человек) | **−14,1** и **−14,5 LUFS** | 1,1 LU |

Разница ~**12 дБ**: в ленте, где предыдущий ролик играл на −14, зритель тянется к громкости
вместо того, чтобы смотреть. Это аргумент про досмотры, а не про аудиофильство.

Цель: **−14 LUFS**, пик **−1 dBTP**, **в два прохода** — первый меряет, второй исправляет по
замеру. Один проход работает вслепую и гоняется за уровнем по файлу, на речи это слышно как
«дыхание» громкости.

```bash
set -o pipefail
# проход 1: замер. JSON вырезается по скобкам: ffmpeg 8 печатает строки ПОСЛЕ него, `tail` его режет
ffmpeg -hide_banner -i готово.mp4 -af loudnorm=I=-14:TP=-1:print_format=json -f null - 2>&1 \
  | sed -n '/^{/,/^}/p' > замер.json
python3 -c 'import json; json.load(open("замер.json"))'   # замер обязан быть валидным JSON
# проход 2: input_i → measured_I, input_tp → measured_TP, input_lra → measured_LRA,
#           input_thresh → measured_thresh, target_offset → offset
ffmpeg -i готово.mp4 -c:v copy \
  -af "loudnorm=I=-14:TP=-1:measured_I=…:measured_TP=…:measured_LRA=…:measured_thresh=…:offset=…:linear=true:print_format=json" \
  -c:a aac -b:a 128k -ar 48000 -shortest -movflags +faststart выдача.mp4
```

- `-ar 48000` обязателен: loudnorm внутри передискретизирует до 192 кГц, и без него выдача
  выходит с AAC 96 кГц (проверено на ffmpeg 8.1.1).
- **Сырая речь почти всегда не влезает в линейный режим.** Разница пик/громкость у дубля 20,5 дБ,
  а −14 LUFS при пике −1,5 допускают 12,5 дБ. Перед двумя проходами — мягкий компрессор и лимитер:
  `acompressor=threshold=0.05:ratio=3:attack=5:release=150:makeup=2,alimiter=limit=0.25:attack=3:release=60:level=disabled`
  (замер: −14,05 LUFS, пик −2,83, LRA 1,0, linear; потолок 0,35 не хватил). Цепочку ставь и в замер,
  и во второй проход. Подробно — журнал ошибок, E21.
- `linear=true` молча откатывается в динамический режим, если пик не помещается под −1 dBTP, —
  а это и есть «дыхание» громкости. В выводе второго прохода проверь
  `"normalization_type" : "linear"`.
- После — замерь выдачу тем же первым проходом (интегральная и пик) и сравни длительность с
  входом.

**Почему последним.** Сначала громкость стояла в первом заходе, замер на −25,8 показал «второй
заход громкость сохраняет». На нормальном уровне это неверно: **−14,2 на входе дали −15,3 на
выходе** HyperFrames. Один замер на нерепрезентативном уровне обобщили в правило. Приводи
громкость над файлом, который уедет зрителю, и меряй результат там же. Побочно исчезает второе
сжатие AAC.

**Ловушка `-shortest`.** AAC дописывает служебные отсчёты, а длительность контейнера берётся по
самой длинной дорожке: без `-shortest` звук вышел на 100 мс длиннее картинки (`67.200 → 67.300`),
и чистовик перестал быть замороженным. Поймала это проверка длительности внутри шага громкости —
шаг, который «просто меняет громкость», не имеет очевидной причины трогать длину, ровно поэтому
проверка там и нужна. Хвост после `-shortest` проверен: дорожка короче на 7 мс, последнее слово
кончается на 67,16 с, запас 33 мс; повторное распознавание до и после — совпадение 0,987, оба
расхождения — разбивка на слова.

## Выдача: потолок битрейта — от ИСХОДНИКА

| | Битрейт | Размер |
|---|---|---|
| сырой дубль | 9,47 Мбит/с | — |
| второй заход HyperFrames, `-q looks` | **15,66 Мбит/с** | 131,6 МБ на 67 с |
| после шага выдачи | **5,46 Мбит/с** | **45,8 МБ** |

Мы отдавали больше бит, чем получили, хотя только вырезали куски и положили сверху плоскую
графику. Правило от исходника, а не от любимого числа: **готовый ролик не превышает битрейт
исходника.** CRF ведёт качество, `-maxrate` только срезает всплески. Вести потолком значило бы
ровный битрейт и неровное качество: на статичной голове биты уходят в никуда, на движении их не
хватает. Качество измерено: SSIM **0,9905** против версии до сжатия на 10-секундном окне,
глазом разницы нет. Для сравнения: площадка всё равно отдаёт зрителю рилсы в 720×1280, около
1 Мбит/с.

```bash
SRC=$(ffprobe -v error -select_streams v:0 -show_entries stream=bit_rate -of csv=p=0 дубль.mp4)
# если N/A — возьми format=bit_rate (весь файл)
ffmpeg -i вход.mp4 -c:v libx264 -crf 20 -maxrate "$SRC" -bufsize "$((2 * SRC))" -pix_fmt yuv420p \
  … -movflags +faststart выдача.mp4
```

`-maxrate` без `-bufsize` libx264 молча игнорирует («VBV maxrate specified, but no bufsize,
ignored») — потолка не будет.

Если выдача перекодирует видео, делай громкость и битрейт одним проходом: один раз видео, один
раз звук, и на выходе проверь все три числа — длительность, громкость, битрейт.

## Каким бывает материал

- **На уже смонтированных рилсах резать нечего.** Три межсловных зазора на 46 с, все 157
  границ — небезопасны. Целевой материал — СЫРЫЕ дубли.
- **В сыром дубле говорящей головы нет смен плана** — 0 на четырёх файлах. Детектор склеек нужен
  для скринкастов, не для одного непрерывного дубля.

## Чего конвейер НЕ делает

Это важнее возможностей — чтобы не ждать того, чего нет:

- не ищет повторы и дубли сам — их указывает агент через `--drop`;
- не трогает кадр: ни кропа под вертикаль, ни слежения за лицом, ни зумов, ни плашек;
- не нормирует и не чистит звук, не подкладывает музыку;
- обрабатывает один файл за запуск;
- джамп-каты видны. Кроссфейд убран намеренно: он съедал речь на краях шва. Стыки смотрит
  человек;
- без ключа распознавателя теряет границы предложений и всю проверку речи.

## Ловушки: весь опыт, который стоил времени

Каждый из этих тупиков выглядит разумной идеей, пока его не пройдёшь.

### Монтаж

- **Резать по таймкодам расшифровки.** Медиана слова 280 мс, а одному «слову» выдано 29,86 с. На
  файле 85,2 с слова до 115,06 с — выдуманный текст на месте тишины.
- **«Рез в 60 мс от границы слова»** выбросил 82 настоящих паузы из 144.
- **«Не задевать надёжное ядро слова»** оставило 38 резов — ещё хуже.
- **Порог тишины от уровня ШУМА** даёт −49 дБ и теряет половину пауз. Считать от речи — около
  −34 дБ.
- **Фиксированный порог** на тихой записи режет речь, на громкой не находит пауз.
- **Автопоиск повторов по фразам-эвристикам** нашёл 0,4 с там, где человек нашёл 47 с. Повторы
  указывает модель.
- **Искать повторы в цельной расшифровке** бесполезно: декодер глотает повтор фразы. Только по
  фразам.
- **Резать фразы по участкам выше порога** — мусор вместо текста: речь проваливается ниже порога
  между слогами. Фраза кончается на паузе от 320 мс.
- **Кроссфейд на стыке** кажется способом спрятать джамп-кат, но съедает речь на краях шва.
- **Конец ролика с запасом 200 мс** обрывается. Нужно 600 мс воздуха.

### Проверка

- **Один аудит на два вопроса.** Первая версия ругалась на 3 файла из 4 с превышением 17–21 дБ.
  Разделили на «тишина внутри» и «стыки дубля» — чисто с запасом 0,2–6,8 дБ.
- **Проверять речь ПОСЛЕ ускорения** бессмысленно: 0,8698 → 0,8478 и три «потерянных» слова,
  которых никто не резал.
- **Слова за длительностью файла** выбрасывать до всякой обработки, иначе они тянут за собой весь
  план реза.
- **Сравнивать повторное распознавание с полным исходником** — выброшенный дубль зачтётся как
  ущерб. Только с тем, что должно остаться.
- **Мягкий порог совпадения (0,80) — не доказательство.** Ниже него сборка откажет, но
  доказывает целость речи только аудит по энергии. Не поднимай порог «для строгости».
- **Итог «убрано / станет / расхождение с планом» при `--drop`** завышен: перекрытие выброса с
  вырезами тишины считается дважды (живой прогон — 8,8 с). Сверяй по факту.
- **Машинные проверки не видят склейку.** Шов смотрит человек. Контактный лист — только первые
  8 швов.
- **Модель побольше** выдумала больше: слова до 135,78 с на файле 105,93 с. Лечит вырезание
  тишины до распознавания, а не размер модели.

### Инструменты

- **`setpts=PTS-STARTPTS/6`** читается как `PTS − (STARTPTS/6)`. Скобки несущие: без них первый
  прогон выдал ролик длиной **1967 с** вместо 71. Ни один аудит этого не поймал, и правильно —
  речь была цела, сломан был темп. Поймало сравнение длительности с планом, которое печатает
  сборка.
- **`atempo` принимает 0,5–2,0 за один проход.** Ускорение ×6 раскладывается на цепочку, иначе
  фильтр откажет.
- **Ключ распознавателя в аргументах команды** виден любому в списке процессов. Только через
  стандартный ввод.
- **libass молча подставит чужую гарнитуру**, если не указать каталог шрифтов.
- **Выравнивание ASS решает, откуда считается отступ:** при выравнивании «верх» `MarginV`
  меряется от верха, и строка легла на 540 вместо 1400 — ровно на лицо.
- **Подпись ниже безопасной линии 1248** перекрывается интерфейсом Instagram. Текст под роликом
  держат коротким.
- **«Рез, затем субтитры»** перекодирует видео дважды — потеря поколения, осознанная плата.
- **`ffmpeg drawtext` ломается на `:` и `,`** в тексте: запятая расщепляет весь граф фильтров.
  Держи фильтры в файле, не собирай их в командной строке.
- **Внутренний `ssh` или `rsync` съедает скрипт**, который подают ему же на вход. Перенаправляй их
  stdin из `/dev/null`.
- **Не тяни сырой PCM через конвейер**, который возвращает вывод строкой — он молча обрежется.
  Пиши в файл.
- **`| tail` прячет код возврата.** Гейт проверяется статусом выхода.
- **AAC без `-shortest`** удлиняет файл на 100 мс — заморозка нарушена.
- **`--silence speed` вместе с `--drop`** не вырезает выброшенное, а проигрывает его ×6. Ни
  аудит, ни проверка речи этого не ловят. С выбросами — только `remove`.
- **ffmpeg без libass** (сборка Homebrew по умолчанию) не знает фильтра `subtitles` —
  `captions.py` падает. Проверяй `ffmpeg -filters` до начала.
- **Пресеты `captions.py`:** у `outline` контур прозрачный (альфа FF), `plate` заливается
  непрозрачным чёрным; `WrapStyle: 2` выключает перенос — длинная строка обрезается краем.
  Смотри один прожжённый кадр до прожига ролика.
- **loudnorm без `-ar 48000`** отдаёт AAC 96 кГц.
- **`-maxrate` без `-bufsize`** libx264 молча игнорирует.
- **HyperFrames:** `<audio>` без `id` — немой рендер; `-w auto` — один поток; `0 sample(s)` в
  `check` значит «не проверялось».

### Инженерия вокруг

- **Правило, реализованное дважды, не закреплено ничем.** Обе половины молча ловят одни и те же
  случаи — ни одну нельзя менять безопасно, и мутационный тест это показывает. Одна реализация;
  остальное выводится из неё, а вывод доказывается свойством на всей области, а не комментарием.
- **Но постусловие — не дубль.** Проверку сняли как «избыточную» и получили: при дробном шаге
  0,1 мс округление даёт индекс за границей массива, а покрытие всё равно считается успешным.
  Перебор нашёл **504** достижимых нарушения. Дубль — вторая независимая реализация правила;
  постусловие проверяет РЕЗУЛЬТАТ вывода одного из другого. Первое убрать, второе оставить.
- **Отказ, проигнорированный в одной ветке, — не отказ.** Рез и аудит научили честно отказывать,
  а в поиске подозрительных мест осталось «нет энергии — пропустить», и результат пришёл
  «успешным» с молча пропавшим отрезком. Проверяй каждое место вызова.
- **Выживший мутант — не шум.** Дважды мутант выжил, и оба раза за этим стоял настоящий дефект,
  которого не видел ни один тест.

Четыре сырых дубля, 6:44 в сумме:

|---|---|---|---|
| только паузы | 404,2 с | 342,2 с | 15,3% |

нужна, чтобы понимать, где кончилась мысль. Разрешать рез может только измеренная энергия звука.
