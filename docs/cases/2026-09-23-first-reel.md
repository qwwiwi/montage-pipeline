## 2. Как шла работа, по шагам

### Подготовка (один раз)

- `ffmpeg-full` из Homebrew. Обычный `ffmpeg` собран **без libass**, и субтитры на нём не
  прожгутся (E5).
- `npm i -g hyperframes`, затем `hyperframes browser ensure`, `doctor` и `skills update`.
- Шрифты Golos Text и Playfair Display Italic, локальная копия GSAP, логотипы SVG.

### Заход 1: чистовик (`roughcut.py`)

1. **`--dry-run`:** порог тишины −41,7 дБ (считается от речи), найдено 39 пауз, план 91 с.
2. **`--silence mark`**, затем распознавание **по фразам**: фраза — речь между паузами от 320 мс,
   каждая распознаётся отдельно. Если распознавать файл целиком, повторы теряются. Запросы к
   распознавателю — с паузой: при лимите 20 запросов в минуту фразы приходили пустыми (E31).
3. **Решение человека №1: что выбросить.**
   - повтор фразы про число продаж: оставлена вторая попытка — она полнее;
   - шум после последнего слова: распознаватель выдумал там «Продолжение следует…».
4. **Сборка** с `--drop`. Порядок обязательный: рез → проверка → ускорение ×1,3.
5. **Решение человека №2: швы.** Лист со всеми 34 швами. Инструмент сам делает только первые 8,
   остальные собраны вручную (E3). Четыре заметных скачка позы закрыты врезками во втором заходе.

### Заход 2: оформление (HyperFrames)

1. **Замер головы** по кадру с сеткой: макушка 430, подбородок 980. По формуле скилла
   (`y0 = 430 − 80 = 350`, `шов ≈ 1490 − (980 − 350)`) шов — граница панели и спикера —
   получился **860 px**.
2. **Распознавание чистовика** с таймкодами слов. Из него берутся субтитры, и к словам привязаны
   все границы врезок.
3. **Генератор `reel/build.py`** собирает композицию кодом, а не руками:
   - хук виден с кадра 0;
   - 4 панели шагов «01 / 04»;
   - врезки «В» и «Т» примерно каждые 3 с;
   - субтитры на шве;
   - призыв с кодовым словом из речи.
4. **Проверки:** `lint` → `check` → проверочный кадр с зонами Reels → правки → рендер `-w 3`.
5. **Выдача `work/deliver.sh`:** громкость в два прохода, потолок битрейта от исходника,
   `-shortest`.

## 3. Уроки

### Съёмка: исправить до монтажа, а не после

- **Выключать кондиционер и вентиляцию.** Гул ниже 120 Гц — главная проблема этого звука: фон
  всего на 18 дБ тише голоса, а нормой считается 40 дБ и больше.
- **Микрофон ближе ко рту или петличка.** Запись шла на −31 LUFS, и ради −14 пришлось поднять
  всё на 17 дБ — гул тоже.
- **Мягкие поверхности в кадре и за камерой:** шторы, ковёр, покрывало. Эхо от голых стен
  фильтрами убирается только частично.
- **Меньше менять позу в паузах.** Четыре шва из 34 дали заметный скачок, их пришлось закрывать
  врезками.
- **Снимать сразу в 30 к/с.** У 60 к/с на рендере 30 к/с набегает лишний кадр (E35).
- **Последнее слово и тишина.** После последнего слова ~1 с тишины, потом не трогать телефон:
  иначе в конце появляется шорох.
- **Шаги называть вслух по номерам:** «первое», «второе», «третье». Панель «01 / 04» встаёт на
  произнесённый номер шага, а в этом дубле было только «во-первых», и границы шагов пришлось
  выбирать по смыслу.

### Монтаж: что подтвердилось

- **Резать только по громкости, не по таймкодам распознавания.** Распознаватель снова выдумал
  текст на тишине («Продолжение следует…»).
- **Повторы ищет человек или агент, по фразам.** Похожий повтор на стыке фраз («ту… ту») оказался
  ложным: одно слово попало в обе фразы (E32).
- **Швы смотреть глазами, все, а не первые 8.**
- **Каждую звуковую обработку проверять повторным распознаванием, а не на слух.**
  - шумодав `afftdn` съедал «то есть» после шва;
  - сильный гейт съедал «и», «где», «у»;
  - итоговая цепочка — самая сильная из тех, что сохраняют все слова.
- **Цепочка громкости из скилла подходит не к любому звуку.** На тихой записи с гулом компрессор
  3:1 ухудшил запас голоса над фоном с 18 до 16 дБ (E37). Сначала замер фона, потом выбор цепочки.
- **Второй заход не должен менять длительность.** Сверять звук до миллисекунды, видео до кадра.

### Оформление: что подтвердилось

- **Проверочный кадр с зонами Reels** на каждом этапе. Он поймал хук в две строки, заголовок во
  всю ширину и чёрный логотип.
- **Логотипы брать только настоящие SVG** из thesvg, gilbarbara или simple-icons. У GetCourse
  открытого логотипа нет, поэтому он дан текстовой плашкой.
- **Смотреть каждый логотип на кадре, а не по имени файла:** `instagram-icon` в gilbarbara
  оказался одноцветным чёрным (E33).
- **Панели держать только в кадрах-сплитах.** Иначе `check` видит текст под врезками и ругается
  на наложение.
- **Тексты на экране брать из речи.** Кодовое слово, цифры и названия сервисов сказаны автором.

## 5. Чек-лист на следующий ролик

**Перед съёмкой**
- [ ] Выключена вентиляция и кондиционер
- [ ] Петличка или телефон ближе ко рту
- [ ] Мягкие поверхности вокруг, 30 к/с, вертикаль
- [ ] Шаги называются вслух по номерам, кодовое слово звучит в конце
- [ ] После последнего слова секунда тишины, телефон не трогать

**Заход 1**
- [ ] `--dry-run`: порог, паузы, аудит
- [ ] `--silence mark` → распознавание по фразам (с паузой из-за лимита запросов)
- [ ] Список выбросов с обоснованием → подтверждение
- [ ] Сборка → проверка тишины и стыков, распознавание ≥ 0,8, длительность по файлу
- [ ] Лист **всех** швов → подтверждение

**Заход 2**
- [ ] Кадр с сеткой → замер головы → шов по формуле
- [ ] Распознавание чистовика → правка отдельных ослышек
- [ ] `build.py`: границы врезок от соседних якорей, точное совпадение слов
- [ ] `lint` 0 ошибок → `check` пройден → кадр с зонами на каждом шаге
- [ ] Рендер `-w 3` → звук совпадает, видео ±1 кадр → SSIM врезок

**Выдача**
- [ ] Замер фона и голоса **до** цепочки громкости
- [ ] Цепочка → повторное распознавание ≥ 0,99, без пропавших слов
- [ ] −14 LUFS, пик ≤ −1 dBTP, linear, битрейт ≤ исходника, длительность = чистовик
